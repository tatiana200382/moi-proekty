# Flowwow через Россию: как настроено

25.11.2026. Проверено.

## Проблема

На Mac включён системный прокси `127.0.0.1:8118` (HTTP и HTTPS). Весь трафик Chrome уходил в Германию:

| Проверка | IP | Страна |
|---|---|---|
| До настройки, через прокси | 2.31.104.44 (Hetzner) | **DE**, Falkenstein |
| Напрямую, без прокси | 146.120.73.71 (Unet) | **RU**, Санкт-Петербург |

В исключениях прокси уже были `avito.ru`, `vk.com`, `max.ru`, `mail.ru` — они ходят напрямую. Flowwow в списке не было, поэтому он шёл через немецкий прокси: отсюда «Москва» вместо Петербурга и странное поведение кабинета.

## Что сделано

В список исключений системного прокси добавлены:

```
flowwow.com
*.flowwow.com
```

Команда:

```bash
networksetup -setproxybypassdomains Wi-Fi \
  "*.avito.ru" "avito.ru" "*.vk.com" "vk.com" "*.max.ru" "*.mail.ru" \
  "localhost" "127.0.0.1" "*.local" \
  "flowwow.com" "*.flowwow.com"
```

## Как проверял

1. **Изолированный тест:** временно добавил в исключения `ipinfo.io` → Chrome показал `146.120.73.71`, Санкт-Петербург, RU. Механизм исключений работает.
2. **Контроль:** убрал `ipinfo.io` из исключений → Chrome снова показал `2.31.104.44`, DE. Значит исключение действует только на указанные домены.
3. **Flowwow:** в браузере город определяется как **Санкт-Петербург**.

## Откат

Резервная копия старого списка: `~/.config/flowwow/proxy-bypass-backup-2026-11-25.txt`.

Вернуть как было:

```bash
networksetup -setproxybypassdomains Wi-Fi \
  "*.avito.ru" "avito.ru" "*.vk.com" "vk.com" "*.max.ru" "*.mail.ru" \
  "localhost" "127.0.0.1" "*.local"
```

## Важно

- Прокси, вероятно, поднимает отдельное приложение. Если оно перезапишет список при следующем запуске — исключения пропадут, Flowwow снова уйдёт в Германию. Проверка: `networksetup -getproxybypassdomains Wi-Fi` и наличие `flowwow.com`.
- В кабинете продавца гео теперь петербургское, как и должно быть.
- Пароли и куки в этом файле не хранятся.

# Как выбирать инструмент: чек-лист

Правило владельца: не брать первый попавшийся вариант. Сначала сравнение, потом выбор.

## Шаг 1. Собрать кандидатов (10–20)

- Основной источник — **GitHub**: поиск по теме, сортировка по звёздам и по дате обновления.
- Дополнительно: официальная документация, обзоры, обсуждения.
- Для мелкой задачи достаточно 5 кандидатов, но не меньше.

## Шаг 2. Отсеять по «здоровью» проекта

| Критерий | Норма | Красный флаг |
|---|---|---|
| Последний коммит | не старше 6 месяцев | больше года тишины |
| Открытые issues | есть ответы авторов | сотни без ответа |
| Лицензия | MIT / Apache / BSD | «только для личного» |
| Документация | есть примеры запуска | только README из трёх строк |
| Зависимости | немного, стандартные | тянет пол-системы |
| Звёзды | от 500 (для узкой задачи — меньше) | 5 звёзд и один автор |
| Безопасность | нет известных уязвимостей | есть CVE без фикса |

## Шаг 3. Отобрать 2–3 лучших

- Сравнить по таблице выше.
- Проверить, что реально решает задачу, а не «в теории».
- Указать: чем выбранный лучше остальных, чем хуже (минусы тоже).

## Шаг 4. Записать вывод

Короткая таблица прямо в задаче или результат:

| Вариант | Звёзды | Обновлён | Лицензия | Вердикт |
|---|---|---|---|---|
| ... | ... | ... | ... | выбран / отклонён, почему |

## Когда не применять

- Текст поста, ответ клиенту, правка файла, простая задача без выбора инструмента.
- Если выбор уже сделан ранее и инструмент работает — не пересматривать без причины.

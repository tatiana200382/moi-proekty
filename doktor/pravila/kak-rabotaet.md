# Как устроен контроль правил

Правила, которые никто не проверяет, соблюдаются «на честном слове». Здесь — механизм, который проверяет их **до** действия, **после** действия и **регулярно**.

Честно о границе: гарантировать 100% нельзя — агент может не вызвать ворота. Поэтому работает связка: ворота (не пускают без условий) + аудит (находит обход) + последствия (стоп после 3 нарушений) + владелец может проверить в любой момент.

## Четыре слоя

| Слой | Что делает | Где |
|---|---|---|
| 1. Реестр | каждое правило → проверка, кто и когда её выполняет | [reestr.md](reestr.md) |
| 2. Ворота | перед риском: план, тест, откат, «да», лимиты | `doktor/pravila/vorota.sh` |
| 3. Аудит | регулярная проверка на обход | `doktor/pravila/audit.py` |
| 4. Последствия | журнал нарушений, стоп после третьего | `doktor/narusheniya.md`, `STOP` |

## Ворота: как это работает

```bash
# перед изменением сервера
doktor/pravila/vorota.sh --tip server --plan plany/2026-11-25-doktor-avtonomnyy.md

# перед публикацией (лимиты площадки)
doktor/pravila/vorota.sh --tip publikaciya --ploshchadka avito

# перед тратой денег или правкой чужого файла
doktor/pravila/vorota.sh --tip dengi --plan plany/xxx.md
```

Ворота **не пропускают**, если:
- нет файла плана или в нём нет строки «Разрешение владельца: получено»;
- нет разделов «Откат» и «Изолированный участок»;
- существует файл `doktor/pravila/STOP` (три нарушения или решение владельца);
- по площадке уже 3 публикации за сегодня или правка была меньше часа назад.

Каждый проход пишется в `doktor/pravila/resheniya.md` и в счётчики площадки. Отказ — тоже запись: видно, что агент не прошёл.

## Аудит: что проверяет

| № | Правило | Как проверяется |
|---|---|---|
| 1 | Секреты не попадают в git | поиск токенов, ключей, паролей в отслеживаемых файлах |
| 2 | Правила меняются только с записью | хеш `PRAVILA.md` сверяется с журналом правок |
| 3 | Планы полные | в каждом файле `plany/` есть «Откат», «Изолированный участок», «Разрешение» |
| 4 | Чужие роли не правятся молча | изменения в `employee.md`, `AGENTS.md` других папок без записи «да» |
| 5 | Файлы не свалкой в корне | корень сверяется с разрешённым списком |
| 6 | Нарушения считаются | 3 записи в `narusheniya.md` → требование остановиться |
| 7 | Стоп-флаг | наличие `STOP` = все агенты останавливаются |

Аудит **не чинит** правила и не удаляет файлы — он показывает факты и пишет нарушения. Решение принимает владелец.

## Последствия

1. Нарушение фиксируется в `doktor/narusheniya.md`: дата, правило, что было, чем подтверждено.
2. Три нарушения — создаётся `STOP`: ворота закрываются, агенты останавливаются до разговора с владельцем.
3. Снимает `STOP` только владелец (`rm doktor/pravila/STOP`).

## Что владелец может проверить сам

```bash
doktor/pravila/audit.py              # полная проверка, код 1 при нарушениях
doktor/pravila/audit.py --json       # то же машинно
cat doktor/narusheniya.md            # все нарушения
cat doktor/pravila/resheniya.md      # все допуски и отказы
```

## Чего механизм не делает

- Не читает мысли: если агент не вызвал ворота и не оставил следов, аудит увидит только последствия (публикацию, коммит).
- Не отменяет решение владельца: любое правило меняется владельцем, а не агентом.
- Не заменяет ответственность: правило «не выдумывать цифры» проверяется по фактам в ответе, а не скриптом.

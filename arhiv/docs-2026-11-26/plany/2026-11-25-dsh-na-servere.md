# План: второй DSH на немецком сервере (когда Мак выключен)

Дата: 25.11.2026. Разрешение владельца: **получено** («положим DSH на сервер»).

## Задача
Когда компьютер выключен, агенты продолжают работать на сервере. Когда включён — работаем с Мака. Файлы проекта должны быть одинаковыми.

## Что уже известно
| Факт | Значение |
|---|---|
| DSH есть в npm | ✅ `@deepseek-ai/dsh`, версия 0.2.2-rc.5 |
| Сервер | Debian/Ubuntu, **1 CPU, 927 МБ RAM**, 16 ГБ свободно |
| Node на сервере | ❌ нет |
| Мак | DSH — Electron-приложение, его сборка только для macOS |

## Шаги
| № | Действие | Проверка |
|---|---|---|
| 1 | Добавить swap 2 ГБ (память маленькая) | `free -h` |
| 2 | Установить Node.js LTS | `node -v` |
| 3 | Установить `@deepseek-ai/dsh` глобально | `dsh --version` |
| 4 | Клонировать репозиторий проекта в `/root/moi-proekty` | `git log -1` |
| 5 | Запустить DSH headless и проверить, что работает | тестовый вопрос |
| 6 | Настроить доступ по HTTPS с паролем (sslip.io + Let's Encrypt + basic auth) | открыть в браузере |
| 7 | Синхронизация: `git pull` перед работой, `git push` после | коммиты видны на обоих |

## Риски и ограничения
| Риск | Что делаем |
|---|---|
| Мало памяти (927 МБ) | swap 2 ГБ; при нехватке — переход на CPX21 (4 ГБ) |
| DSH на Linux ≠ приложение на Mac | интерфейс будет веб, не оконный |
| Открытие наружу | HTTPS + пароль + fail2ban |
| Секреты в репозиторий | не попадают (правило PRAVILA) |

## Откат
```
systemctl disable --now dsh
rm -rf /root/moi-proekty ~/.npm-global/lib/node_modules/@deepseek-ai
swapoff /swapfile && rm /swapfile
```

## Порядок
Сначала шаги 1–3 и проверка, что DSH вообще запускается на этом сервере. Только потом доступ снаружи.

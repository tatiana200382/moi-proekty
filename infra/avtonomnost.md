# Автономность: как работать при выключенном Mac

**Задача.** Процессы ИИ-команды должны выполняться по расписанию и по событию, даже когда ноутбук выключен.
**Критерий «готово»:** задача выполнена без включённого Mac, есть запись в логе с датой и результат (пост, отчёт, карточка заявки) — проверяю по факту, а не «должно работать».

Дата: 2026-11-25.

## Что проверено фактами

| Факт | Проверка |
|---|---|
| Агенты живут в приложении DeepSeek Harness на Mac, CLI-версии нет | `which dsh` — пусто; в приложении только GUI |
| Отдел продаж крутится launchd-задачей каждые 5 минут | `~/Library/LaunchAgents/ru.silversong.zayavki.plist.off` — сейчас **выключена** (`.off`) |
| Цикл заявок зависит от Chrome на 9224 и macOS-путей | `otdel-prodazh/tools/run.sh` |
| **Свой сервер уже есть**: `2.31.104.44`, 1 ядро, 1 ГБ RAM, 19 ГБ диска, Debian/Ubuntu, python3 + git, без node и Chromium | `ssh root@2.31.104.44 'nproc; free -m; df -h'` — 2026-11-25 |
| Сейчас сервер занимается только SSH-туннелем | `ru.silversong.socks.plist` → `ssh -N -D 127.0.0.1:1082` |

Вывод: **покупать сервер не нужно** — нужен вопрос «что из процессов вообще можно гонять без Mac».

## Варианты

| # | Вариант | Что заработает при выключенном Mac | Срок | Деньги (оценка) | Риски |
|---|---|---|---|---|---|
| **A** | **Текущий VPS + cron, без браузера** | Отчёты, бэкапы, диагностика Доктора, постинг через API ВК/Telegram, генерация текстов через LLM API, алерты о сбоях | 1–2 дня | 0 ₽ (сервер уже оплачен) | Не тянет Chrome: 1 ГБ RAM |
| **B** | **Апгрейд VPS до 2 vCPU/4 ГБ + Playwright** | Всё из A + чтение заявок с Авито/Карт/ВК в headless-браузере | 1–2 недели | Апгрейд — уточнить в панели перед оплатой (порядок: 1–2 тыс. ₽/мес) | Куки и капчи, IP датацентра, антибот-защита площадок |
| **C** | **n8n на своём VPS / Make / Albato** | Готовые сценарии «событие → действие» без кода | 3–5 дней на 2–3 сценария | n8n сам по себе бесплатен, хостинг из A/B; Make/Albato — подписка за операции | Логика переезжает в узлы, наши промпты и правила придётся переписать |
| **D** | **Домашний мини-ПК или Raspberry Pi, всегда включён** | Всё, включая браузер и локальные файлы; домашний IP, знакомые сессии | 3–7 дней | Оборудование + электричество; оценка 3–15 тыс. ₽ разово | Нужен стабильный интернет и питание; Mac всё равно выключается — это не Mac, но и не облако |
| **E** | **Гибрид: облако ставит задачи, Mac исполняет** | Только «лёгкое»; тяжёлое ждёт включения Mac | 2–3 дня | 0 ₽ | Не решает главного: пока Mac выключен, тяжёлые задачи стоят |
| **F** | **Mac не выключать: сон по расписанию + автологин** | Всё, что уже есть, без миграции | 1 вечер | 0 ₽ (счёт за электричество) | Это не автономность: ноутбук должен быть включён и в сети |

## Чего не бывает

- **Бесплатно и полностью автономно.** Любой вариант требует постоянно включённого устройства: сервер, мини-ПК или сам Mac.
- **Переноса браузерных задач «как есть».** Chrome на Mac с вашими куками не переезжает: на сервере нужен headless-браузер и заново выполненные входы.
- **Обхода защит.** Если площадка (Авито, ВК) видит автоматизацию с серверного IP — это лечится только официальными API и сервисными аккаунтами, а не «ещё одним прокси».

## Рекомендация: три этапа

**Этап 1 — сегодня-завтра, 0 ₽.** На существующем VPS: cron для того, что не требует браузера — ежедневный отчёт в MAX/Telegram, бэкап области, диагностика Доктора, проверка, что сайт и карточки живы. Плюс алерт в Telegram, если задача не отработала. Mac при этом можно выключать.
*Проверка:* выключить Mac, дождаться времени задачи, получить сообщение и запись в логе сервера.

**Этап 2 — 1–2 недели.** Апгрейд VPS до 2 vCPU/4 ГБ, установка Playwright, перенос **одного** браузерного процесса (например, чтения заявок с карт) с отдельным сервисным входом. Мерить: сколько заявок поймали, сколько потеряли, не банит ли площадка.
*Проверка:* сутки без Mac, сравнение числа заявок с сутками на Mac.

**Этап 3 — по результату этапа 2.** Или переносим остальные браузерные процессы на сервер, или оставляем их на Mac по расписанию пробуждения, а в облаке держим только «лёгкое».

**Почему так, а не сразу «всё в облако»:** на 1 ГБ RAM и без node браузер не поедет; а переносить сразу всё — значит две недели без работающих заявок вместо одного дня.

## Что понадобится в любом варианте

- API-ключ LLM для сервера (отдельный, чтобы не светить основной).
- Токены ВК/Telegram/MAX — в переменных окружения сервера, не в git.
- Один канал алертов («задача не выполнилась») — иначе автономность превращается в тишину.
- Переход на «сервисные» аккаунты там, где автоматизация разрешена правилами площадки.

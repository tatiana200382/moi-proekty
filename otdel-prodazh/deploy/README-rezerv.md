# Схема «сервер + копия на Mac»

Дата: 24.11.2026.

## Как устроено

```
        ┌──────────────────────────┐
        │  Домашний сервер (24/7)  │  ← основной: опрос Авито, ВК, заявки в MAX
        │  /opt/silversong         │
        └────────────┬─────────────┘
                     │ health-проверка (порт 8790)
        ┌────────────▼─────────────┐
        │  Mac (копия + резерв)    │  ← код и доступы; включается, если сервер молчит
        │  standby.sh каждые 15 мин│
        └──────────────────────────┘
```

## Что где лежит

| Что | Сервер | Mac |
|---|---|---|
| Код (git) | да | **да, копия** |
| Токен бота MAX | да | **да** |
| Cookies Авито | да | **да** (на случай переезда) |
| Опрос по расписанию | **да** | только в резерве |
| Обработка фото | нет | да |

## Как работает резерв

1. На сервере запущен `health-server.py` — отвечает `{"ok": true}` и временем последнего опроса.
2. На Mac каждые 15 минут `standby.sh` спрашивает сервер.
3. Три неудачных проверки подряд → Mac запускает опрос сам и пишет в чат:
   «⚠️ Сервер не отвечает — включился резерв на Mac».

**Дублирования нет:** пока сервер жив, Mac молчит.

## Что нужно, чтобы это заработало

1. **SSH-доступ** к серверу (логин и пароль или ключ).
2. Запустить `bootstrap.sh` на сервере.
3. Перенести токен и cookies.
4. Включить `standby.sh` на Mac (LaunchAgent, раз в 15 минут).

## Проверка

| Проверка | Ожидание |
|---|---|
| Выключить Mac | заявки продолжают приходить |
| Выключить сервер | через ~45 минут Mac включает резерв и пишет предупреждение |
| Включить сервер | резерв снова замолкает |

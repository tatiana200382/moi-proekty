# Выбор инструментов отдела продаж

Правило владельца: не хвататься за первый инструмент, сравнивать 10–20 кандидатов, брать топовые, записывать вывод. Проверка — 11.11.2026.

## Критерии

| Критерий | Порог |
|---|---|
| Звёзды и форки | от 3 000 звёзд, живой форк |
| Последний коммит | не старше 6 месяцев |
| Открытые issues | не больше 500, иначе сырость |
| Лицензия | понятная, пригодная для коммерческого использования |
| Документация | есть быстрый старт и примеры |
| Вес и зависимости | поднимается на одном сервере или ноутбуке |
| Безопасность | нет открытых критичных дыр, есть 2FA/роли |
| Активность | релизы и ответы в issues |

## Что рассмотрели

22 репозитория — полная таблица с цифрами в [`katalog-github.md`](katalog-github.md). Категории: CRM, единый inbox, автоматизация, аналитика, базы, телефония, рассылки.

## Шорт-лист: 3 инструмента + 1 мост

| Место | Инструмент | Зачем | Цена | Когда |
|---|---|---|---|---|
| 1 | **Google Sheets / CSV** (мост) | единая таблица обращений сегодня, без сервера | 0 ₽ | сейчас |
| 2 | **Chatwoot** | один inbox: ВК, Telegram, WhatsApp, сайт | 0 ₽ self-host, нужен сервер | 2–4 недели |
| 3 | **Twenty CRM** | клиенты, сделки, воронка, задачи | 0 ₽ self-host | когда строк >300 |
| 4 | **n8n** | автоматизация: заявка → таблица → напоминание | 0 ₽ self-host | после inbox |

**Почему Chatwoot, а не «мессенджеры по отдельности».** Сейчас ВК, Telegram и WhatsApp живут в трёх окнах; 11 непрочитанных — следствие. Chatwoot собирает их в одну очередь с назначением ответственного и историей. Это прямо лечит главную потерю.

**Почему Twenty, а не Odoo/EspoCRM.** Twenty — 60 749 звёзд, коммит 11.11.2026, 110 открытых issues, современный интерфейс. Odoo — ERP на всё, 11 298 issues и тяжёлая настройка; EspoCRM — крепкий, но PHP-стек и меньше экосистема; SuiteCRM — 1 372 issues, ощущается устаревшим.

**Почему n8n.** 210 026 звёзд, ежедневные коммиты, 1 250 issues — много, но проект живой. Закрывает автоматизацию без программиста: «новая заявка → строка в таблице → напоминание через 2 часа».

## Почему не остальные

| Инструмент | Почему нет |
|---|---|
| Odoo | ERP целиком, слишком тяжёл для трёх магазинов |
| SuiteCRM | 1 372 открытых issues, устаревший интерфейс |
| EspoCRM | рабочий, но оставляем запасным: PHP + MySQL |
| Krayin | хороший MIT-вариант, но меньше интеграций; запасной |
| Mautic, listmonk | рассылки — зона Марты, не продаж |
| Cal.com | запись на встречи, у нас заказы, а не слоты |
| Baserow, NocoDB | базы, не CRM; можно заменить таблицу позже |
| Metabase | дашборды — после появления данных |
| Formbricks | опросы и отзывы — зона Марты |
| erxes | 955 issues, сырее конкурентов |
| Evolution API, Baileys | неофициальный WhatsApp, риск блокировки номера — не берём |
| Asterisk, MikoPBX | телефония; только после решения владельца о переадресации |
| Evidence | отчёты из SQL — позже, нужен аналитик |

## Решение

1. **Сегодня:** таблица в Google Sheets + CSV-шаблон, ВК/Telegram/WhatsApp вручную, телефон как есть.
2. **Через 2–4 недели:** Chatwoot — при условии, что есть сервер и человек на настройку. Без этого не начинать: «поставили и не настроили» хуже, чем одна таблица.
3. **CRM:** Twenty — когда таблица станет тесной (300+ строк или 3+ пользователя).
4. **Автоматизация:** n8n — после того, как процессы в таблице устоялись.
5. **Телефония:** отдельное решение владельца. Пока три номера в магазинах, ИИ не может принять звонок.

## Чего мы не проверили

- Цифры — с GitHub API на 11.11.2026, **запуском не проверяли**.
- Скорость развёртывания Chatwoot/Twenty на нашем Mac не измерялась.
- Лицензии Chatwoot, Twenty, n8n, Metabase, Baserow, NocoDB, Mautic, erxes отмечены как `NOASSERTION` — перед коммерческим внедрением проверить вручную.

Пересмотр — раз в квартал или при смене задачи. Следующий — 09.02.2027.

# Решение: один немецкий IP через SSH-SOCKS

Дата: 25.11.2026. Работает. Проверено на Маке.

## Суть

Туннель на **SSH** к нашему серверу в Германии. Ничего не устанавливается, права администратора не нужны, маршруты не меняются.

| Компонент | Что |
|---|---|
| Туннель | `ssh -N -D 127.0.0.1:1082 root@2.31.104.44` |
| Автозапуск | LaunchAgent `ru.silversong.socks` (перезапускает при обрыве) |
| Системный прокси | SOCKS5 `127.0.0.1:1082` |
| Исключения | `*.avito.ru`, `*.vk.com`, `*.max.ru`, `*.mail.ru`, localhost |

## Проверки (все пройдены)

| № | Проверка | Результат |
|---|---|---|
| 1 | Внешний IP через туннель | ✅ `2.31.104.44` |
| 2 | Safari → chatgpt.com | ✅ открылся, вход выполнен |
| 3 | Авито через исключение | ✅ открылся (российский IP) |
| 4 | Telegram | ✅ 5–6 соединений через туннель |
| 5 | Приложение ChatGPT | ✅ 30 соединений через туннель |
| 6 | Большой файл (100 КБ) | ✅ скачался целиком |
| 7 | Обрыв туннеля | ✅ агент поднял заново |

## Почему сработало, а WireGuard — нет

| Что | Итог |
|---|---|
| WireGuard (UDP) | рукопожатие есть, данные не ходят |
| Shadowsocks (TCP, sing-box) | соединение есть, данные не ходят |
| **SSH (TCP)** | ✅ **работает полностью** |

Проверка сети напрямую: 30 КБ в обе стороны проходят. Значит канал исправен — проблема была в конкретных реализациях туннелей, а не в сервере.

## Управление

| Задача | Команда |
|---|---|
| Проверить | `curl -x socks5h://127.0.0.1:1082 https://api.ipify.org` |
| Перезапустить | `launchctl kickstart -k gui/$(id -u)/ru.silversong.socks` |
| Выключить прокси | `networksetup -setsocksfirewallproxystate "Wi-Fi" off` |
| Включить прокси | `networksetup -setsocksfirewallproxystate "Wi-Fi" on` |

## Ограничения

- Прокси действует на приложения, которые **используют системные настройки** (браузеры, ChatGPT, Claude, Telegram — проверено).
- Приложения со **своими** настройками сети требуют отдельной настройки.
- Если сервер недоступен — интернет пропадёт у этих приложений; вернуть: выключить прокси (одна команда).

## Telegram через туннель (25.11.2026)

Telegram не использует системный прокси — у него своя настройка. Включено:

| Параметр | Значение |
|---|---|
| Тип | SOCKS5 |
| Сервер | `127.0.0.1` |
| Порт | `1082` |
| Как включить | в приложении — ссылка `tg://socks?server=127.0.0.1&port=1082`, затем «Подключить» |

**Проверено:**
| Проверка | Результат |
|---|---|
| Соединения Telegram на `127.0.0.1:1082` | ✅ 7 |
| Соединения к Telegram DC с немецкого сервера | ✅ 44 |
| Приём и отправка сообщений | ✅ работает |

**Откат:** Telegram → Настройки → Продвинутые → Тип соединения → удалить прокси.

## Почему после перезагрузки не открывался GPT (25.11.2026)

**Причина:** при загрузке система стартовала туннель **раньше**, чем появилась сеть. SSH отвечал «Timeout, server not responding», агент завершался. Сторож видел, что туннеля нет, и **выключал системный прокси** (так задумано, чтобы интернет не пропадал). В итоге GPT шёл напрямую — и получал **403** (регион не поддерживается).

**Что исправлено:**
| Что | Было | Стало |
|---|---|---|
| `KeepAlive` | `true` (перезапуск всегда) | `SuccessfulExit: false` + **`NetworkState: true`** — перезапуск только когда есть сеть |
| Тайм-аут подключения | по умолчанию (долго) | **`ConnectTimeout=10`** |
| Пауза между попытками | по умолчанию | **`ThrottleInterval: 5`** |

**Проверено после исправления:**
| Проверка | Результат |
|---|---|
| Порт 1082 | ✅ открыт |
| `chatgpt.com` через туннель | ✅ **200** |
| Выходной IP | ✅ `2.31.104.44` |
| Системный прокси | ✅ включён |
| Telegram через туннель | ✅ соединения есть |

**Откат:** `cp ~/Library/LaunchAgents/ru.silversong.socks.plist.bak-* ~/Library/LaunchAgents/ru.silversong.socks.plist` и `launchctl bootout/bootstrap`.

## Почему GPT (приложение) не открывался, а Telegram работал (25.11.2026)

**Причина:** приложение ChatGPT/Codex — на движке Chromium. Chromium **не использует системный SOCKS-прокси**, он читает только **HTTP/HTTPS** прокси. После перезагрузки был включён только SOCKS → приложение шло напрямую → **403**.

**Что сделано:**
| Что | Значение |
|---|---|
| Системный HTTP-прокси | `127.0.0.1:8118` (локальный HTTP → SOCKS) |
| Системный HTTPS-прокси | `127.0.0.1:8118` |
| Список исключений | тот же (Авито, ВК, MAX, Mail.ru) |
| Сторож | теперь включает/выключает **все три** прокси вместе |

**Проверено:**
| Проверка | Результат |
|---|---|
| Приложение ChatGPT | ✅ открылось, чаты загрузились, модель «GPT-6 Luna» |
| Соединения приложения через прокси | ✅ 19 |
| Пропускная способность через 8118 | ✅ 2,9 МБ/с |
| `chatgpt.com` через 8118 | ✅ 200 |

**Откат:** `networksetup -setwebproxystate "Wi-Fi" off` и `-setsecurewebproxystate "Wi-Fi" off`.

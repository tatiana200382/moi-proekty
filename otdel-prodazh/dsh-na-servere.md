# Второй DSH на немецком сервере

## Зачем он нужен (по словам владельца)

Владелец **всегда работает с Мака**. Серверный DSH нужен для одного: чтобы, когда Мак выключен, **агенты и ассистент продолжали работать**, а не останавливались.

| Устройство | Роль |
|---|---|
| **Мак** | рабочее место владельца — там идёт вся работа |
| **Сервер** | «дежурный» экземпляр: тот же проект, тот же ключ модели, автозапуск |

Из этого следует:
- серверный DSH — **не замена** Маку, а страховка;
- сессии не переносятся (каждая машина хранит свои), но **файлы проекта общие** через синхронизацию;
- всё, что должно пережить выключение Мака, держим **на сервере** (systemd-службы и таймеры), а не на Маке.

## Доступ

| Что | Значение |
|---|---|
| Адрес | `https://2-31-104-44.sslip.io:8443/` |
| Логин (basic auth) | `silver` |
| Пароль | пароль прокси (в файле доступов) |
| Токен входа | в файле `Обучение ИИ/токен-DSH-сервер.txt` |
| Полная ссылка | `https://2-31-104-44.sslip.io:8443/?token=…` |

Токен нужен **один раз** на браузер — он ставит cookie. После перезапуска службы токен меняется:
```
ssh root@2.31.104.44 "journalctl -u dsh-web -n 60 --no-pager | grep -o 'token=[A-Za-z0-9_-]*' | tail -1"
```

## Синхронизация файлов

| Что | Где |
|---|---|
| Скрипт | `~/Library/Application Support/silversong/sync-workspace.sh` |
| Ярлык на Рабочем столе | `Обучение ИИ/Синхронизировать-проект.command` |
| Копия в проекте | `otdel-prodazh/tools/sync-workspace.sh` |

Правило: **новее — побеждает**, удаления не переносятся. Тяжёлые папки (`arhiv`, картинки, `*.zip`, `*.pdf`) не синхронизируются.

## Откат
```

rm -f /etc/systemd/system/dsh-web.service /etc/nginx/sites-enabled/dsh-server
nginx -t && systemctl reload nginx
```

# AGENTS.md

Правила для ИИ-агентов, работающих в этой папке.

## Что это за проект

Учебная папка «Мои проекты»: здесь собираются небольшие рабочие материалы для малого бизнеса — тексты, письма, сводки, таблицы. Папка наполняется по одной задаче за раз, без сложной структуры.

## Базовые правила

- **Язык.** Общение с пользователем и содержимое документов — по-русски, если пользователь не попросил иначе.
- **Краткость.** По умолчанию пиши коротко: одна мысль — один абзац, без «воды» и общих рассуждений.
- **Формат.** Основной формат файлов — Markdown (`.md`). Для таблиц используй markdown-таблицы, для перечислений — списки.
- **Имена файлов.** Латиница, строчные буквы, слова через дефис: `hello.md`, `summary.md`, `plan-prodazh.md`. Никаких пробелов и кириллицы в именах.
- **Проверяй перед созданием.** Сначала посмотри, что уже лежит в папке, и не дублируй существующие файлы — дополняй их.
- **Не удаляй чужое.** Файлы пользователя не удаляй и не перезаписывай без явного разрешения.

## Структура

```
Мои проекты/
├── AGENTS.md    — правила (этот файл)
├── hello.md     — приветствие и список возможностей ассистента
└── summary.md   — сводка по содержимому папки
```

Новые файлы кладутся в корень папки; подпапки — только если файлов одного типа станет больше пяти.

## Работа со сводкой

`summary.md` — актуальный обзор папки на одну страницу. Обновляй его, когда:

- добавлен или удалён файл;
- заметно изменилось содержание существующего документа.

В сводке: таблица файлов, краткое содержание каждого и выводы. Держи её в пределах одной страницы.

## Стиль документов

- Приветствие — дружелюбное, но без эмодзи-перебора (максимум один-два на документ).
- Примеры задач — конкретные, привязанные к малому бизнесу: клиенты, деньги, время.
- Цифры и факты — только реальные; если данных нет, прямо пиши «данных нет», а не выдумывай.

## GitHub

Папка — git-репозиторий. Все агенты работают через GitHub, а не «в столе».

- **Перед работой** проверь `git status`; если репозиторий не инициализирован — `git init` и первый коммит.
- **После каждой задачи** — коммит с коротким описанием по-русски: `git add -A && git commit -m "что сделано"`.
- **Публикация** — `git push` в репозиторий GitHub, когда он подключён. Адрес и состояние доступа — в `github.md`.
- **Удалённый репозиторий не настроен** — не выдумывай адрес, а скажи об этом и предложи подключить.
- **Никогда не коммить:** токены, пароли, cookie (`cookies.env`), `.browser-profile/`, `.env`, личные данные клиентов. Секреты лежат вне папки.
- **Тяжёлое — не в репозиторий:** изображения больше 5 МБ, архивы, `.aiff`, `.docx`; они уже в `.gitignore`.
- **Конфликты и чужие правки:** сначала `git pull --rebase`, при расхождении — остановись и спроси, не перезаписывай чужие изменения.

## Голос

Владелец просит, чтобы в любом новом окне и новом чате все ответы звучали голосом.

- После каждого текстового ответа озвучивай короткий пересказ: `./skazat.sh "текст" 175` (голос Milena, русский).
- Читай только вывод — 2–4 предложения. Без перечисления файлов, цифр из таблиц и списков.
- Голос не отменяет текст: сначала текст в чате, потом озвучка.
- Долгие документы целиком не читать — только итог и следующий шаг.
- Если звук не воспроизвёлся — сказать об этом одной строкой и не повторять попытку больше двух раз.

## Как объяснять (владелец — новичок)

Владелец учится работать с нейросетями с нуля. Даже настройки и кнопки даются сложно.

- Объясняй простыми словами; новый термин — сразу переводи на бытовой язык.
- Действия — по шагам: что нажать, где это находится, что появится на экране.
- Одна обучающая вставка за ответ (понятие, вопрос или аналогия), не больше.
- Не считай ничего «очевидным». Если есть выбор из двух вариантов — объясни разницу.
- Если владелец застрял — предложи сделать самому, а не объяснять заново.

# Авито: цена контакта, заявки и оплаты на CSV

Проверено на учебном CSV `agent-marketolog/avito/uchebnye-dannye/avito-30-dney.csv` (30 дней, 2 объявления), 2026-11-21.

## Когда применять

- Нужно посчитать CPL, CPQL, CPA по выгрузке объявлений.
- Сверить свои расчёты с тем, что Авито считает контактом и просмотром.
- Найти, где формула врёт, и предложить одно изменение в отчёте.

Не применять: для вакансий (другая логика откликов) и для услуг с длинным циклом сделки без когортного учёта.

## Входные данные

CSV с полями (обязательные помечены):

| Поле | Смысл | Примечание |
|---|---|---|
| `date` * | дата | для разреза по неделям и когортам |
| `ad` * | объявление | одна строка = один день одного объявления |
| `spend_rub` * | расходы за день | тариф + продвижение; если можно — раздельно |
| `views` | просмотры | не путать с показами |
| `contacts` * | контакты | звонок, чат, показ номера; повторы за 24 ч считаются один раз |
| `qualified` * | квалифицированные заявки | заявка с поводом, датой и бюджетом |
| `paid` * | оплаченные заказы | факт оплаты |
| `revenue_rub` | выручка | сумма оплат |

Минимум для расчёта: `date`, `ad`, `spend_rub`, `contacts`, `qualified`, `paid`.

## Формулы

```
CPL  = Σ spend / Σ contacts        # цена контакта
CPQL = Σ spend / Σ qualified       # цена квалифицированной заявки
CPA  = Σ spend / Σ paid            # цена оплаты
CR1  = Σ qualified / Σ contacts    # контакт → квалификация
CR2  = Σ paid / Σ qualified        # квалификация → оплата
ROAS = Σ revenue / Σ spend
```

Правила проверки:

1. Считать **только через суммы**, не средним из средних. Среднее недельных CPL ≠ общий CPL.
2. Если знаменатель 0 — писать «нет данных», не 0.
3. Метрики считать по каждому объявлению и по всем вместе.
4. Проверять, что `contacts ≥ qualified ≥ paid`; иначе искать ошибку выгрузки.
5. Расходы сверять: `Σ spend` из CSV = расход из «Финансов» кабинета на ту же дату.

## Действия

1. Проверить CSV: обязательные поля, типы, пустые строки, дубли дат по одному объявлению.
2. Свести итоги: `spend`, `contacts`, `qualified`, `paid`, `revenue`.
3. Посчитать CPL, CPQL, CPA, CR1, CR2, ROAS — по всем и по каждому объявлению.
4. Сверить с тем, как Авито считает контакты: повторные звонки и чаты за 24 часа — один контакт; просмотр телефона — тоже контакт.
5. Сравнить с ориентирами: цена оплаты не выше валовой маржи с заказа (у нас ~2 100 ₽ при чеке 3 850 ₽ и марже ~55%).
6. Предложить **одно** изменение в отчёте с обоснованием цифрами из этого же CSV.
7. Записать результат в `agent-marketolog/avito/otchet-metriki-ГГГГ-ММ-ДД.md`.

## Контроль результата

| Проверка | Ожидание |
|---|---|
| Сумма расходов | совпадает с кабинетом |
| Воронка | contacts ≥ qualified ≥ paid |
| Формулы | пересчитаны через суммы, не средние |
| Нулевые знаменатели | «нет данных», не 0 |
| Вывод | одна метрика-приоритет и одно изменение |

## Типовые ошибки

1. **Среднее из средних.** Средние CPL по неделям дают другой результат, чем Σ spend / Σ contacts.
2. **Просмотры вместо контактов.** Просмотр — открытие карточки; контакт — действие покупателя.
3. **Повторные контакты.** Авито считает уникальные за 24 часа; если выгружать сырые события — двойной счёт.
4. **Расходы только на продвижение** или только на тариф: цена контакта занижается или завышается.
5. **Лаг оплаты.** Оплата может прийти позже контакта; при подсчёте по месяцу оплаты CPA скачет.
6. **Нулевые продажи** → деление на ноль, «0 ₽» вместо «нет данных».
7. **Смешение объявлений** в одной строке — метрики по объявлениям становятся бессмысленными.

## Сверка с официальной логикой

- Контакт: звонок, сообщение, показ номера. Повторные за 24 часа — один контакт (справка Авито, статистика).
- Просмотр: открытие объявления; в тарифе за просмотры оплачивается именно он.
- Показы ≠ просмотры.
- Цена целевого действия в Авито Рекламе считается как расход / целевые действия в отчёте кампании.
- Отчётность в кабинете: «Аналитика → Статистика», сравнение с конкурентами, расходы в «Финансах».

## Одно изменение, которое предлагаю в отчёте

Перейти с CPA «по месяцу оплаты» на **когортный CPA**: делить расходы на заявки, а оплаты считать по тем же заявкам, даже если оплата пришла позже. Причина: при лаге в 1–3 дня CPA по месяцу завышается в конце периода. В учебном CSV перенос двух оплат на следующий месяц поднимает CPA с 700,6 до 794,0 ₽ — ошибка 13% только из-за границы периода.

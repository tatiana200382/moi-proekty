# План: вернуть Flowwow управляемый Chrome в видимое окно

Дата: 2026-11-25. Тема: доступ к кабинету Flowwow. Автор: Марк.

## 1. Что меняю

Способ запуска управляемого Chrome (порт 9224, профиль `.chrome-profile`): убрать флаг `--headless=new`, всё остальное оставить как есть.

Было (проверено через `chrome://version`):

```
/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --disable-gpu \
  --remote-debugging-port=9224 --user-data-dir="<проект>/.chrome-profile" \
  --lang=ru --no-first-run --noerrdialogs
```

Станет: та же команда без `--headless=new`.

## 2. Зачем

Flowwow отдаёт «Forbidden» на все страницы, включая публичную страницу магазина, при том что `curl` с обычным User-Agent с того же IP получает HTTP 200. Chrome сейчас представляется как `HeadlessChrome/158`. Пункт 4 правила «как человек» требует видимое окно, не headless. Без браузера не открыть кабинет: заказы, остатки, фото, статистику.

## 3. Как проверю, что сработало

| Проверка | Критерий |
|---|---|
| 1. Публичная страница магазина в новом Chrome | открывается, виден заголовок магазина, а не «Forbidden» |
| 2. `flowwow-auth.mjs check` после входа владельца | «кабинет продавца ОТКРЫТ» |
| 3. Дашборд через меню | видны заказы и статистика |

## 4. Проверка на изолированном участке

- Где: второй экземпляр Chrome, временный профиль, порт 9333.
- Результат: **не выполнена** — Chrome под окружением DSH не стартует («sandbox initialization failed», процесс падает). Временный профиль удалён.
- Значит первый запуск видимого окна — единственная проверка, и делать её нужно с разрешения владельца и сразу с откатом наготове.

## 5. Откат (без участия агента)

```
pkill -f "remote-debugging-port=9224"
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --remote-debugging-port=9224 \
  --user-data-dir="/Users/tatiana/Desktop/Обучение ИИ/proekty/Мои проекты/.chrome-profile" \
  --lang=ru --no-first-run --noerrdialogs &
```

Откат возвращает прежнее состояние: кабинет снова недоступен, API и чтение работают как сейчас.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Закроются открытые вкладки (Авито, ВК, Яндекс.Бизнес) | сессии в профиле сохраняются, но недописанные сообщения могут потеряться — перезапуск в согласованное время |
| Видимое окно занимает экран | окно обычного размера, закрывается одним нажатием |
| Защита сайта всё равно откажет | тогда причина не в headless — возвращаемся к разбору, не обходим защиту |

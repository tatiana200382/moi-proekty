# План: ежедневный аудит правил на сервере

Дата: 2026-11-26. Разрешение владельца: **получено** («тогда делай»).
Тема: аудит правил работает без включённого Mac.

## 1. Что меняю

- На сервере `2.31.104.44` появляется копия репозитория `/opt/doktor/repo` (клон `--depth 1`, только чтение).
- Раз в день (09:00 МСК) systemd-таймер запускает `doktor/pravila/audit.py` из этой копии.
- Есть нарушения — тревога в Telegram-бот Котика с перечнем; нет — тихая запись в журнал.
- Если репозиторий не обновился или аудит упал — тревога «аудит не выполнен».

## 2. Зачем

Сейчас аудит запускается вручную на Mac. Когда Mac выключен, нарушения (правка правил без записи, секрет в коммите, неполный план) копятся незамеченными.

## 3. Как проверю, что сработало

| № | Проверка | Критерий |
|---|---|---|
| 1 | Аудит запускается таймером | `systemctl list-timers doktor-audit.timer` — есть следующий запуск |
| 2 | На чистом репозитории | `FAIL 0` |
| 3 | На подсунутом нарушении (фейковый токен в файле) | `FAIL 1`, тревога в Telegram |
| 4 | Повторная тревога | не приходит (анти-спам, как у сторожа) |
| 5 | Репозиторий обновляется | `git -C /opt/doktor/repo log -1` не старше суток |
| 6 | Откат | `systemctl disable --now doktor-audit.timer` → служба не работает |

## 4. Проверка на изолированном участке

- Где: `/root/audit-test` на сервере, снимок репозитория (tar), без доступа к рабочей копии.
- Результат: (заполняется после прогона)

## 5. Откат (без участия агента)

```
systemctl disable --now doktor-audit.timer
rm -f /etc/systemd/system/doktor-audit.timer /etc/systemd/system/doktor-audit.service
rm -rf /opt/doktor/repo /var/lib/doktor-audit
systemctl daemon-reload
```

Доступ к GitHub отзывается удалением deploy-ключа в настройках репозитория.
